## 一、战斗流程状态机（规则书 4.1-4.5）

```
[宣战] 袭击/反击袭击/同灵脉袭击 → 进入战斗
  ↓
阶段1 战斗开始时（4.1）
  展露环境 → 双方定参战单位与战斗位 → 查魔力不足惩罚
  → 冲锋宣言（骑乘/Lancer：+20% 或属性差+50%判定）
  → 展露计算表+常驻技能 → 能力提交/响应 → 结算 → 战术选择 → 战术对抗结算
  ↓
阶段2 初始工序（4.2）
  确认计算表 → 能力提交/结算 → 双方主力位选[主要属性] → 骰定[随机属性]
  ↓
阶段3 主要工序（4.3）
  确认计算表 → 能力提交/结算（宝具/主要技能）→ 展露
  ↓
阶段4 最终工序（4.4）
  确认计算表 → 死斗宣言（主力位，+20%，不可撤退）→ 能力提交/结算 → 决胜检定
  ↓
阶段5 战斗结束时（4.5）
  确认胜负 → 等级魔耗结算（超下限消散）→ 战败方全单位成战胜方主力位俘虏
  ※ 任一时点一方战斗位清空 → 立即跳入战斗结束时
```

引擎职责：计算表实时维护 + 每工序结算能力效果 + 决胜检定 + 战后清算；
能力提交的**收录与响应等待**由 GM/QQ 交互驱动（引擎在每工序等"提交完毕"信号）。

## 二、战斗位与战场宽度（规则书第三节）

| 位置 | 属性计入 | 限制 |
|---|---|---|
| 主力位 | 全额 | 每方至少 1 个；退场后按辅助→仆役→支援递补 |
| 辅助位 | 减半 | 宽度≥3 |
| 仆役位 | 减半 | 仅仆役单位；宽度≥4 |
| 支援位 | 不计入 | 可发动礼装与[支援]技能宝具；不计算等级魔耗；常驻能力总是生效 |

宽度 n 的位组合：1=主｜2=主+支｜3=主+辅+支｜4=主+辅+仆+支｜5=主+辅×2+仆+支｜6=主+辅×3+仆+支｜7=主+辅×4+仆+支。

## 三、胜率链（规则书第六节 + Excel 公式）

### 3.1 胜率的构成
- 对己任一单位的胜率补正 +1 / 对敌方任一单位的胜率惩罚 +1 → 己方胜率 +1
- 战斗属性（辅助/仆役减半、支援不计）每点 → 己方 +1
- 双方主力位每点等级 → 己方 +1
- 双方胜率互相抵消至总值 100

### 3.2 基础胜率（三属性对抗 → 计算表）
对抗属性 = [袭击方主力主要属性, 被袭击方主力主要属性, 随机属性]；逐项比优/平/劣：

| 得分（优3/平2/劣1） | 基础胜率 |
|---|---|
| 3优（9分） | 90% |
| 2优1平 | 80% |
| 2优1劣 | 70% |
| 1优2平 | 60% |
| 3平 / 1优1平1劣 | 50% |
| 2平1劣 | 40% |
| 1优2劣 | 30% |
| 1平2劣 | 20% |
| 3劣 | 10% |

（与 Excel D86 一致；前端 useBattleCalculator.mapScoreToBaseRate 已移植 ✅）

### 3.3 最终胜率链（Excel E 列公式，前端已移植 ✅）
```
蓝方累计 = 基础胜率 + 等级差 + 属性补正(每点属性=1点) + 战前修正 + 初始工序 + 主要工序(含死斗+20)
红方同理
胜率差 = 蓝累计 − 红累计 → K 值 → 实际胜率 = (K + 50) 按公式折算
保底：clamp 到 [己方底限胜率, 100 − 对方底限胜率]（底限默认 10%）
可选规则·差值减半：双方主力都为从者时，与 50:50 的差距减半（底限导致的胜率不减半）
```

### 3.4 魔力不足惩罚（战斗开始时查）
**已定稿（GM 09-07）：采用规则书线性口径**——魔力不足状态下每 -20 → 除回路外全属性 -10（常驻，随不足消失而恢复），合计惩罚后任一属性不低于 5。Excel 档位表（-40=-10/-60=-15…）**废弃不用**。
引擎行为：按线性口径计算"建议惩罚"展示，**支持 GM 手填覆盖**（实际带团惯例是 GM 手填）。

### 3.5 战术（规则书 6.2）
克制环：**强击 > 破袭 > 试探 > 扼守 > 强击**；被克制则效果无效。
- 强击：自身除宝具外任一属性 +20
- 破袭：敌方主力[底限穿透 -20%]
- 试探：己方无损撤退 FP-1
- 扼守：自身 +20% 胜率

### 3.6 指令
- 冲锋（骑乘持有者/Lancer）：目标不在战斗位→强制拉入敌方战斗位+自身+20%；在位→随机四属性判[属性差+50%]，成功+20%/失败[底限穿透-10%]
- 死斗（主力位，最终工序）：+20% 胜率，最终工序内不可撤退

### 3.7 决胜检定
按实际最终胜率骰 D100。已录判例：成功率≥100% 自动成功。

## 四、结算链多级排序（5.2，工序内能力结算顺序）

```
令咒（最优先）
→ 效果链：轰击/即死 → 状态 → 属性修正 → 胜率修正 → 底限/最终胜率 → 魔力修正 → 文本
→ 能力链：宝具 → 技能 → 工房/神殿/礼装构件
→ 类型链：宝具[对人魔剑→对人→对人魔剑→对军→视为对城→对城→结界→对界]
          技能[职介→天赋→技艺→祝福→荣冠→兵器→魔术]
→ 等级链：EX→A→B→C→D→E→[-]
→ 时机链：常驻 → 指定工序 → 随时
→ 状态链：抗性→特性赋予→封印→晕眩→恐惧→魅惑→迟滞→石化→灼伤→感电→中毒
多效果能力按首个效果类型归类；含轰击/即死/必胜文本必按该类型结算。
```
⚠️ 引擎实现：第一版按「效果链→能力链→时机链」三级排序（等级/状态链待模板库补充）。

## 五、撤退与 FP（规则书第七节）

- FP 初始 1/人（仆役无 FP）
- 撤退消耗：初始 1 / 主要 2 / 最终 3 / 战斗结束 4（阵营内每人各付）
- 特殊：7.2.2 对方主力为仆役→己方仅需 1FP；7.2.3 己方主力为御主、对方为从者→无法撤退（人偶御主除外）；7.2.4 仅战斗位单位付 FP 可带同灵脉全部己方单位撤退
- 试探战术：无损撤退 FP-1；本选试探机制（准备期撤退 FP>2 返还 1FP；本选期从者 FP 失效且撤退+1）
- 战败方：战败灵脉全部单位成战胜方主力位俘虏；进入游荡状态（判定上限 10%、疲惫判定、无圣杯供魔）

## 六、引擎边界（自动 vs GM）

| 引擎自动 | GM/需裁决 |
|---|---|
| 计算表维护（属性合计/减半/等级） | 战斗位的人员安排确认 |
| 基础胜率/最终胜率链全计算 | 技能宝具发动的**提交与响应顺序**（人际交互） |
| 战术克制判定 | 效果文本的复杂联动（模板库未覆盖的） |
| 魔力不足惩罚 | 冲锋/死斗等宣言的触发的记录（引擎算效果） |
| 决胜检定掷骰 | 俘虏/游荡的后续处置 |
| 等级魔耗/清算 | |

## 七、实现规划（battle.mjs）

| 件 | 内容 |
|---|---|
| `battle.mjs` 核心函数 | `createBattle`(编队+宽度) / `applySkill`(效果分类入链) / `settlePhase`(工序结算) / `calcWinRate`(胜率链) / `finalJudge`(决胜) / `afterBattle`(清算) |
| 表 `engine_battles` | 战斗主记录：地点/双方编队/战术/工序状态/胜率分解(JSON)/结果 |
| 表 `engine_battle_effects` | 工序内能力发动记录（结算链排序字段） |

| 验收 | 离线回放一场模拟战斗（双从者主力、全工序、含战术克制与死斗）→ 胜率链逐步输出与手算对照 |

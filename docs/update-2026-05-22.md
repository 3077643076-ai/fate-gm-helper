# 更新日志 2026-05-22 — P1：契约系统 + 角色卡补充字段

## 新增功能

### 一、契约系统（御主↔从者绑定）

**后端新增文件：**

| 文件 | 说明 |
|------|------|
| `backend/.../domain/Contract.java` | 契约实体，字段：id / campaign / masterCard / servantCard / status / manaSupplyLimit / 时间戳 |
| `backend/.../repository/ContractRepository.java` | 数据库操作（按战役查、按御主查、按从者查） |
| `backend/.../service/ContractService.java` | 业务逻辑：setServantContract（换绑）、removeServantContract、breakContract |
| `backend/.../web/ContractController.java` | REST API（PUT/DELETE `/api/contracts/servant-contract` 用于换绑） |
| `backend/.../web/dto/ContractRequest.java` | 请求体 |
| `backend/.../web/dto/ContractResponse.java` | 响应体 |

**API 端点：**

| 方法 | 路径 | 说明 |
|------|------|------|
| `PUT` | `/api/contracts/servant-contract` | 设置从者的契约御主（自动解除旧契约，支持换绑） |
| `DELETE` | `/api/contracts/servant-contract` | 解除从者的契约绑定 |
| `GET` | `/api/contracts?campaignId=X` | 查询战役下全部契约 |

**前端 UI：** 契约作为"当前回合信息表"中的一行（在令咒行下方），每格两个下拉框：

1. **契约类型**：`从者→御主` / `御主→从者`
2. **契约对象**：根据类型显示可选的目标列表（显示代号方便GM确认）

设置后**自动双向同步**：如果槽位A的从者绑定了槽位B的御主，槽位B会自动显示"御主→槽位A的从者"的反向记录。选"解除绑定"即可取消。

前端文件：`frontend/src/services/contract.js`（API调用），契约逻辑直接写在 BattleControl.vue 的 orchestrator 中。

### 二、角色卡补充字段（规则书 RC1.15）

**后端修改：**

CharacterCard 实体新增三个字段：

| 字段 | 数据库列 | 类型 | 说明 |
|------|----------|------|------|
| `hiddenAttribute` | `hidden_attribute` | String | 隐属（天地人星兽），影响属性克制 |
| `traits` | `traits` | JSON(List\<String\>) | 特性列表，如 ["神性","魔性","骑乘"]，影响特攻判定 |
| `specialAttack` | `special_attack` | TEXT | 特攻描述，如"对神性特攻+20%" |

需要 `StringListJsonConverter`（JSON ↔ List\<String\> 的 JPA 转换器）。

CharacterStatus 新增：

| 字段 | 数据库列 | 类型 | 说明 |
|------|----------|------|------|
| `supplyMana` | `supply_mana` | Integer | 本回合从契约御主获得的供魔值 |

**Excel 解析器映射（useExcelParser.js）：**

从者模板（RC1.15从者角色卡.xlsx）：
- `M8` → hiddenAttribute（隐属）
- `M6` → traits（特性，逗号分隔）
- `M2` → specialAttack（特攻列表）

御主模板（RC1.15御主角色卡.xlsx）：
- `M6` → traits（特性）
- `M2` → specialAttack（特攻列表）
- 无隐属字段（御主不适用）

新增 `readCellList()` 函数，支持中英文逗号、顿号分隔。

## 改进（P0 延续）

### Koishi 指令优化
玩家现在可以可选指定行动类别：
```
从者行动 剑 攻击 敌方从者          # 不指定类别，自动检测
从者行动 剑 干涉 攻击敌方从者       # 指定为干涉类别
御主行动 弓 信息 侦察冬木教会       # 指定为信息类别
```
类别支持中文别名输入（机动/干涉/攻击 等），指令帮助也更新了。

### 前端行动顺序表
- 从错误的8类（含"摧毁工房"）改为规则书正确的9类（机动/魂食/干涉/解放/制造/信息/休整/协助/介入）
- 优先使用后端返回的 `phaseType`，兜底用文本关键词检测

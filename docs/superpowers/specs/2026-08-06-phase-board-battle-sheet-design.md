# 工序面板型网页战斗表设计

## 目标

把当前网页战斗表升级成可以实际跑团使用的“工序面板型战斗表”。它不追求一次性替代 GM 裁决，而是按照规则战斗流程引导 GM：编队、检查常驻、逐工序确认技能、预览技能影响、最终结算、保存快照和回写状态。

## 设计原则

1. **不强行全自动裁决**：系统负责算明确数值，GM 负责决定技能是否生效、生效等级、复杂效果如何处理。
2. **按工序推进**：页面主流程为 `编队 → 常驻检查 → 战斗开始时 → 初始工序 → 主要工序 → 最终工序 → 决胜结算`。
3. **保留手动表习惯**：保留战前胜补、胜怯、属性补正、保底、最终胜率链条等字段名和计算含义。
4. **技能原文永远可见**：结构化效果用于辅助计算，原文用于 GM 查证和裁决。
5. **任何自动结果都可追踪**：最终胜率必须能看出来自哪些技能、哪些手动补正、哪个工序。

## 页面结构

### 1. 顶部战斗状态栏

显示当前战役、回合、战斗表保存状态、结算锁定状态。

操作按钮：
- 保存战斗表
- 复制/保存战斗快照
- 确认结算并回写状态
- 解除本地临时修改（只清当前未保存输入，不删历史）

### 2. 左侧工序导航

固定显示工序：

1. 编队
2. 常驻检查
3. 战斗开始时
4. 初始工序
5. 主要工序
6. 最终工序
7. 决胜结算

每个工序显示状态：
- 未处理
- 有待确认技能
- 有需 GM 裁决项
- 已确认

GM 可以自由切换工序，但最终结算前会提示还有哪些工序未确认。

### 3. 中间工序工作区

当前工序的主要操作区。

#### 编队工序

- 蓝方从角色卡选择主力、辅助、支援。
- 黄方可以手填，也预留以后从敌方卡选择。
- 辅助属性自动半值计入。
- 展示双方总属性。

#### 常驻检查工序

系统自动收集双方所有 `timing = 常驻` 的技能模板，默认加入队列并设为“开启”。

GM 可以对每个常驻技能执行：
- 保持开启
- 关闭本场生效
- 修改生效等级
- 标为需裁决
- 写入裁决备注

适用场景：
- 石化之魔眼这类复杂常驻技能不自动处理。
- 技能被封印、降级、失效。
- 条件不满足但仍要留下记录。

#### 战斗开始时 / 初始 / 主要 / 最终工序

系统按技能模板的发动时机收集技能。

非常驻技能默认状态为“待确认”，不会自动生效。

GM 可操作：
- 生效
- 不发动 / 不生效
- 修改生效等级
- 选择目标
- 选择属性（例如魔力放出选择筋力/耐久/敏捷）
- 标为需裁决
- 添加手动补正

### 4. 技能结算队列

每个工序都有一列技能队列。每行包含：

- 阵营：蓝方 / 黄方
- 角色：例如 Saber 阿尔托莉雅
- 技能名：例如 魔力放出B
- 原等级：角色卡等级
- 生效等级：GM 可改
- 时机：常驻 / 战斗开始时 / 初始工序 / 主要工序 / 最终工序 / 随时
- 状态：默认开启 / 待确认 / 已生效 / 已关闭 / 需裁决
- 自动影响摘要：例如 筋力 +10，己方胜率 +5%

队列排序规则：
1. 当前工序优先。
2. 常驻在最前。
3. 同一工序内按蓝方、黄方、主力、辅助、支援排序。
4. GM 可以手动调整顺序；调整结果保存到战斗表快照。

### 5. 右侧影响预览栏

点击某个技能后，右侧显示：

- 技能原文
- 结构化效果
- 生效等级
- 生效条件
- GM 备注
- 是否需要手动裁决
- 应用前结果
- 应用后预览结果

示例：

```text
魔力放出B
生效等级：B
选择属性：筋力
自动影响：筋力 +10，己方胜率 +5%
应用前：基础胜率 80%，最终胜率 62.5%
应用后：基础胜率 90%，最终胜率 75%
```

如果效果无法自动计算，则显示：

```text
石化之魔眼B
需 GM 裁决：石化判定、目标范围、状态赋予
系统不会自动修改胜率。请在手动补正区填写结果。
```

### 6. 右侧固定结算摘要

始终显示当前战斗结果摘要：

- 双方总属性
- 当前对比属性
- 优 / 平 / 劣
- 基础胜率
- 等级差
- 属性差
- 战前胜率
- 初始工序胜率
- 主要工序胜率
- 最终工序补正
- 保底 / 上限
- 最终胜率
- 魔力消耗与剩余
- 未处理警告

这个摘要随着 GM 勾选技能、修改等级、填写手动补正实时更新。

## 数据模型设计

当前 `battle_sheet` 已有字段：
- `blue_positions`
- `yellow_positions`
- `activated_skills`
- `mana_data`
- `group_a_stats`
- `group_b_stats`
- `win_rate_result`

第一版不急着拆新表，优先把新版状态存进 JSON 字段，减少迁移成本。

建议新增或扩展 JSON 结构：

### phaseState

存入 `group_a_stats` 或未来新增字段。

```json
{
  "currentPhase": "MAIN",
  "phases": {
    "PASSIVE": { "confirmed": true },
    "BATTLE_START": { "confirmed": false },
    "INITIAL": { "confirmed": false },
    "MAIN": { "confirmed": false },
    "FINAL": { "confirmed": false }
  }
}
```

### skillQueue

记录每个技能在本场战斗中的结算状态。

```json
[
  {
    "id": "blue:MAIN:魔力放出",
    "side": "blue",
    "position": "MAIN",
    "characterId": 1,
    "characterName": "Saber 阿尔托莉雅",
    "skillName": "魔力放出",
    "originalRank": "B",
    "effectiveRank": "B",
    "phase": "MAIN",
    "status": "APPLIED",
    "selectedStat": "strength",
    "target": "self",
    "manualJudgment": false,
    "gmNote": "本次选择筋力",
    "appliedEffects": [
      { "kind": "stat_modifier", "stat": "strength", "value": 10 },
      { "kind": "win_rate_modifier", "target": "self", "value": 5 }
    ]
  }
]
```

状态枚举：
- `AUTO_ON`：常驻默认开启
- `PENDING`：待 GM 确认
- `APPLIED`：已生效并进入计算
- `DISABLED`：本场关闭或不发动
- `MANUAL`：需 GM 裁决，不自动进入公式

### manualCorrectionsByPhase

每个工序都允许手动补正。

```json
{
  "BATTLE_START": {
    "blue": { "stat": {}, "winRate": 0, "guarantee": 0, "note": "" },
    "yellow": { "stat": {}, "winRate": 0, "guarantee": 0, "note": "" }
  },
  "INITIAL": {},
  "MAIN": {},
  "FINAL": {}
}
```

## 计算规则

### 自动进入公式的效果类型

第一版支持：

- `stat_modifier`：属性补正
- `win_rate_modifier`：己方胜率补正
- `enemy_win_rate_modifier`：敌方胜率补正
- `guarantee_modifier`：保底胜率补正
- `mana_cost`：魔力消耗
- `select_stat_modifier`：GM 选定属性后转成 `stat_modifier`

### 不自动裁决的效果

以下只进入提示和手动裁决：

- 石化
- 即死
- 反击
- 支援
- 抗性上升 / 抗性无效
- 技能降级本身
- 状态层数自动增减
- 战术变更
- 目标选择复杂的范围效果

这些效果显示原文和结构化提示，由 GM 决定是否填入手动补正或备注。

### 生效等级

每个技能有 `originalRank` 和 `effectiveRank`。

GM 可以手动把 `effectiveRank` 改成 A/B/C/D/E/EX 或“无效”。

系统根据 `effectiveRank` 读取模板中的等级数值。例如：

魔力放出：
- A：属性 +15，胜率 +5
- B：属性 +10，胜率 +5
- C：属性 +5，胜率 +5

如果模板暂时没有分等级结构，则沿用当前模板固定效果，并提示“此模板未拆等级”。

## 保存与结算

### 保存

保存内容包括：
- 编队
- 战术
- 当前工序
- 每个工序确认状态
- 技能队列状态
- 手动补正
- 魔力消耗
- 当前胜率结果

### 确认结算

点击确认结算时：

1. 检查是否还有 `PENDING` 技能。
2. 检查是否还有未确认工序。
3. 如果有 `MANUAL` 技能，提示 GM 确认已经处理。
4. 保存最终快照。
5. 回写蓝方已选角色魔力。
6. 锁定战斗表。

## 第一版交付范围

第一版要做到“可以用来跑常规战斗”：

- 工序导航 UI
- 技能队列 UI
- 常驻技能默认开启、可关闭
- 非常驻技能待确认、可生效
- GM 可修改生效等级
- GM 可选择属性类技能的属性
- 点击技能显示影响预览
- 已生效技能按工序汇总进最终胜率链条
- 手动补正按工序保存
- 未处理技能/未确认工序提示
- 保存和确认结算继续可用

第一版暂不做：

- 完整状态系统自动联动
- 石化 / 即死 / 反击 / 支援自动裁决
- 黄方从角色卡选择
- 多方混战
- AI 自动判定
- 完整 md 自动导入

## 后续扩展

第二版可以做：
- 黄方也从角色卡或敌方库选择。
- 技能模板支持按等级存储效果数组。
- 条件半自动判断，例如战术是否被克制、是否主力位。
- 状态效果和角色状态联动。
- 战斗快照历史列表。

第三版再做：
- Q&A 判例面板。
- AI 规则助手只给建议，不自动修改战斗表。

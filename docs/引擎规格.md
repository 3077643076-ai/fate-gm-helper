# 三国杯行动引擎规格（YGO 式自动机）v0.1 草案

> 目标（GM 09-03 定调）：结算引擎用确定性代码——像游戏王自动对战，玩家只出选择，
> 引擎结算+播报，可完全不用 AI；AI 唯一职责是判例答疑（可选，后接）；GM 只在引擎
> 标记「需裁决」时介入。
> 动机（09-07 追加）：①token 成本——AI 带团每句都烧钱，引擎零 token；②稳定性——
> SOP 是提示词级约束，引擎是程序级约束，AI 没有整活的空间。
> 本文档是唯一行为规格；代码实现与本文档冲突时，以本文档为准并修订文档。

---

## 一、架构与位置

```
玩家 QQ 群（私组/灵脉群/公屏）
    │ .指令（结构化）为主；私组公告解析为辅
    ▼
fate-actions 插件（Koishi，QQ 通道，已有）          dsh/AI（可选）
    │ HTTP                                          │ 判例答疑 kb /advise
    ▼                                               ▼
引擎 API（backend-node /api/engine/*）←── 需裁决队列 ──┘
    │
引擎核心（纯函数，无副作用）：
    parser（指令/公告解析）→ settler（结算器）→ judge（判定器）
    → broadcaster（播报器）→ groupPort（群管理端口）
    │
SQLite 状态库（唯一事实源，复用现有表 + 引擎新表）
    │
网页引擎面板（GM：状态/队列/推进/裁决）
```

原则：**引擎核心是纯函数**（输入=当前状态+指令，输出=新状态+播报+群管理指令集+
需裁决项），所有副作用（写库、发 QQ）由外壳执行——可测试、可重放、可回滚。

## 二、状态模型

| 表 | 内容 | 来源 |
|---|---|---|
| `campaign_round` | 当前回合/时段（OPEN/CLOSED） | 已有 |
| `character_status` | 角色×回合的魔力/令咒/状态 | 已有，引擎主导写入 |
| `mana_ledger` | 魔力流水（每笔一行） | 已建（轨 A） |
| `judgment_ticket` | 判定单（投点登记制） | 已建（轨 A） |
| `alias_registry` | 别名注册表 | 已建（轨 A） |
| `mana_rules` | 魔力口径表 | 已建（轨 A） |
| `skill_template` | 能力模板（名字→权威数值） | 已建（轨 A） |
| `leyline` / `leyline_assignment` | 灵脉属性与归属 | 已有 |
| `engine_unit_location`（新） | 角色当前所在灵脉（实时，非按回合） | 引擎新表 |
| `engine_active_effects`（新） | 场上生效效果（结界/宝具/buff，可见性与补正都查它） | 引擎新表 |
| `engine_pending_ruling`（新） | 需裁决队列（编号/上下文/AI 猜测/状态） | 引擎新表 |
| `engine_group_binding`（新） | 灵脉群映射（灵脉名→群号）+ 成员清单 | 引擎新表 |

## 三、玩家指令集（第一版：不含战斗）

格式：`.行动 <动词> [目标]`（私组发，职阶从群名识别——沿用 fate-actions 现状）。

| 动词 | 目标 | 结算链阶段 | 说明 |
|---|---|---|---|
| 机动 | 灵脉 | 机动 | 移动；成功后触发群管理（拉群/退群） |
| 潜入 | 灵脉 | 机动 | 隐蔽移动；结算后需掷[潜入判定]（口径待录） |
| 干涉 | 灵脉 | 干涉 | 对外灵脉行动（西城/剑阁有拦截判定） |
| 留守 | - | （不占链） | 驻扎声明 |
| 魂食 | - | 魂食 | 人流>0 才可；供魔=成功60+回合末60（口径已录） |
| 奏乐 | - | 制造/行动 | 洛阳限定；60% 判定；+30魔与[乐不思蜀1] |
| 征兵 | - | 制造 | 长坂坡限定；30魔+40%判定 |
| 托孤 | 己方单位 | 解放 | 白帝城限定；每御主限1 |
| 解放 | - | 解放 | 开鲜血神殿等（特裁：不耗行动） |
| 潜入侦查/广侦/情报调查/礼装制作/休整 | - | 信息/休整 | 判定类行动，走判定单 |
| 转魔 | X-Y N | （即时台账） | 沿用现有 .转魔 |

解析链（复用轨 A 别名回退链）：精确名 → 别名 → 拼音 → 编辑距离 → 团内类型推理
（泛用指代）→ 失败进需裁决。**动词不在指令集内 → 需裁决（不瞎猜行动类别）**。

## 四、时段循环（GM 驱动）

```
GM: .推进
  ├─ 前置检查：①所有判定单已 attached（或 void）②需裁决队列空 ③口径已冻结
  ├─ 按结算链处理本时段全部行动：
  │    机动 → 魂食 → 干涉 → 解放 → 制造 → 信息 → 休整 → 摧毁工房
  ├─ 判定：引擎直接掷骰（D100，确定性随机；记录在判定单）——不再依赖玩家手投
  ├─ 灵脉效果结算（每条效果查 leyline.effect 原文口径）
  ├─ 对账：账本 SUM vs 角色状态，不一致 → 中止播报，报告 GM
  ├─ 供魔/上限：按 mana_rules 口径表计算（脚本算，永不口算）
  ├─ 状态落盘（角色状态/灵脉归属/生效效果）
  └─ 播报 + 群管理指令集执行
GM: .裁决 <编号> <内容>   → 需裁决队列处理
GM: .状态                → 引擎视角当前局面
```

**判定归属的简化**：引擎自动掷骰后，玩家手投（.ra）仅作娱乐/信任参考；
玩家坚持手投时走判定单（轨 A 流程）。目标值口径全部来自口径表/灵脉效果原文。

## 五、群管理端口（GroupPort）——本次新覆盖

引擎结算产生的**群管理指令集**，由 QQ 通道执行：

| 指令 | 触发 | API（NapCat/Koishi） | 状态 |
|---|---|---|---|
| 改群名 | 灵脉状态变化 | set_group_name | ✅ 已验证可用 |
| 发公告 | 时段播报 | _send_group_notice | ✅ 已验证可用 |
| 发消息 | 组内回执 | send_group_msg | ✅ 已验证可用 |
| 拉人入群 | 机动/潜入成功进新灵脉群 | ⚠️ 标准清单无此 API | 实测：send_packet 兜底 / 邀请链接 / GM 待办 |
| 移出群 | 离开灵脉群 | set_group_kick（机器人须管理员） | 实测 |
| GM 待办 | 以上任何失败 | engine_pending_ruling 转入 | 兜底路径 |

**灵脉群即状态**（沿用现惯例）：群名 = 灵脉名+魔力量/人流量/战场宽度，由引擎同步；
成员 = 当前位于该灵脉的全部玩家（主从）。

## 六、播报器（分级出口 + 可见性）

- 私组：本组结算回执（直通）
- 灵脉群：本灵脉变化——**先查 engine_active_effects 的隐藏效果**（如[魔术结界：
  鲜血神殿]隐藏遮蔽魂食信息）；禁露职阶与配对，一律代号
- 公屏：仅 GM 指定播报（截止时间/全局事件）；同一原则
- 公告去重：每群每类只保留最新一条

## 七、需裁决（AI 与 GM 的边界）

进队列：动词不认识 / 目标解析失败 / 规则原文含糊 / 口径未录 / 数值对不上账。
处理：`.裁决 <编号> <内容>` → 引擎按裁决继续；可沉淀项（别名/口径/判例）回写库。
AI 答疑（可选）：dsh 或网页侧调 kb /advise，只解释规则出处，**永远不写引擎数据**。

## 八、里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 状态模型三新表 + 指令解析 + 时段推进 + 判定器（引擎掷骰）+ 账本对账 | 离线试跑一个时段：7 组行动→结算→对账全对 |
| M2 | 灵脉效果结算（11 脉口径全录）+ 群管理端口（改群名/公告/消息自动化；拉群实测） | 真实时段试点：引擎播报 vs GM 手工核对 |
| M3 | 战斗引擎（战斗表公式后端化，复用 useBattleCalculator 移植） | 战斗结算全自动 |
| M4 | AI 退到答疑层；网页引擎面板完善 | 全程零 AI 参与 main loop |

## 九、成本与稳定性对比（动机备忘）

| | AI 带团（现状） | SOP+AI（轨 A） | 引擎（轨 B） |
|---|---|---|---|
| token 成本 | 高（每时段持续对话） | 中 | **零**（仅答疑按需） |
| 规则稳定性 | 靠记忆，会忘 | 提示词约束，偶发跳步 | **确定性代码，不会忘** |
| 魔力/判定 | 人工/半人工 | 脚本辅助+AI 抄账 | **引擎全算** |
| 复杂裁决 | AI 猜（危险） | 需裁决队列 | 需裁决队列（同一机制） |
| 开发成本 | 零 | 1-2 天 | M1+M2 约 1-2 周（渐进可用） |

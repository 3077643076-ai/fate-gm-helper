# 行动表 Excel 记录（action-log-xlsx）

把用户的行动指令写入行动表 Excel，单元格定位与《圣杯玩家指令总控.xlsx》完全一致：
第 35 行=跳伞；之后每天两行（昼行=从者、下一行=御主；夜行=从者、下一行=御主）；列 F..L 对应 弓/杀/骑/枪/剑/术/狂。

## 默认目标文件

- `X:\dev\dev\fate-gm-helper-main\1.15\三国杯玩家指令总控.xlsx`（三国杯专用，未创建时先 init）
- 群聊记录：`X:\dev\dev\fate-gm-helper-main\1.15\群聊记录-三国杯.jsonl`（机器人自动落盘，每行一条 JSON）
- 其他战役请向用户确认文件名。

## 群聊导入工作流（机器人落盘 → AI 总结填表）

机器人（fate-actions 插件）会把收到的群聊**原样记到** `1.15/群聊记录-三国杯.jsonl`（独立于 Excel 写入，最可靠）。用户说「把群里的行动整理进 Excel / 看群聊记录」时：

1. **转可读聊天记录**（比直接读 JSONL 省 token）：
   ```
   python "<skill_dir>\scripts\action_log.py" chatlog --file "1.15\群聊记录-三国杯.jsonl" --lines 200
   ```
   （可按群过滤：`--guild <群ID>`）

2. **提取行动指令**：从记录里找出 `.从者行动 …` / `.御主行动 …` / `.介入 …`，解析出：从者还是御主、职阶（群名/内容首词/发言者名单）、内容。含糊的（没写职阶、群名不含阶职）先问用户或按名单推断，别猜。

3. **逐条写入 Excel**：按下面「标准流程」的解析用 `record` 写入；同一时段多人的按顺序写。写入前先 `status` 看当前时段是否与群聊时间一致，不一致就 `advance`/`set-day` 对齐。

4. **回报**：哪些人哪天的行动已录入、哪些看不懂需要 GM 确认。

## 标准流程

1. **确保文件存在**：若默认文件不存在，运行：
   ```
   python "<skill_dir>\scripts\action_log.py" init --file "X:\dev\dev\fate-gm-helper-main\1.15\三国杯玩家指令总控.xlsx"
   ```
   （init 会从 1.15/圣杯玩家指令总控.xlsx 模板复制并清空行动记录区；`--clear-roster` 可同时清空基本信息名单。）

2. **看现状**（名单、当前第几天昼/夜、已填内容）：
   ```
   python "<skill_dir>\scripts\action_log.py" status --file "<目标文件>"
   ```

3. **解析指令**：
   - `.从者行动 <内容>` → `--role SERVANT`；`.御主行动 <内容>` → `--role MASTER`
   - 职阶（弓/杀/骑/枪/剑/术/狂）：从 status 的名单或用户语境推断；拿不准就向用户确认，不要猜。
   - 内容 = 指令关键字之后的部分，原样保留（如 `机动-灵脉-C`）。
   - 天/时段：默认用状态文件里记录的当前天/时段（status 会显示）；用户明确说「第X天昼/夜」「跳伞」时显式传 `--day`/`--period`。

4. **写入**：
   ```
   python "<skill_dir>\scripts\action_log.py" record --file "<目标文件>" --role SERVANT --class 弓 --text "机动-灵脉-C"
   ```
   - 格子已有内容默认用「，」合并追加（重复内容自动跳过）；要覆盖整格加 `--overwrite`。
   - 想先看结果不落盘：加 `--dry-run`。
   - 多人连续提交同一时段时按上面的解析逐条 record 即可；写完后确认返回信息。

5. **推进时段**：整轮（该时段各职阶都提交完）后运行 `set-day` 推进到下一时段（跳伞 → 第1天昼 → 第1天夜 → 第2天昼 …）：
   ```
   python "<skill_dir>\scripts\action_log.py" set-day --file "<目标文件>" --day 2 --period DAY
   ```

6. **更新交接文档**（每次记录完行动，或用户说「写交接/交接文档」时必做）：
   ```
   python "<skill_dir>\scripts\action_log.py" handoff --file "<目标文件>" --out "X:\dev\dev\fate-gm-helper-main\1.15\三国杯交接.md"
   ```
   文档包含：当前第几天昼/夜、已记录格子数、行动记录总览表、名单、下次继续的说明。回报时告知用户文档路径。

## 新会话接续

- 用户再次开团说「记录行动」时，**先读 `1.15/三国杯交接.md`**（存在的话），再运行 `status` 确认最新状态，然后继续记录。
- 交接文档与 `status` 互为补充：交接文档适合快速浏览，`status` 是权威实时数据。

## 机器人实时写入（NapCat + Koishi）

`my-koishi-bot` 的 fate-actions 插件已支持实时写入同一份 Excel：群里发 `.从者行动 <内容>` / `.御主行动 <内容>` 会自动写进 `xlsxPath` 对应的行动表（同时提交后端）；`.下一时段` 推进时段；`.行动表` 查看状态。AI 会话主要用于：手动补录、判例、生成/刷新交接文档，以及处理机器人写不进的情况（如 Excel 被打开占用）。

## 注意事项

- 脚本只改目标 xlsx 的格子、同目录 `.state.json`（记录当前天/时段）和交接文档，不动其他文件。
- 行动内容原样写入，不做「-」→「至」之类的改写；GM 想统一格式可在 Excel 里再编辑。
- 用户没说是哪个战役/哪个文件时，默认按三国杯处理并明确告知用户写到了哪里。
- 写入后向用户简要回报：哪一天/昼或夜、哪个职阶、从者还是御主、写了什么。
- 交接文档默认输出到 xlsx 同目录 `<标题>交接.md`；三国杯建议固定用 `--out "1.15/三国杯交接.md"` 保持单一文件。

## 规则查证（可选，防幻觉）

对行动类别含义/限制有疑问时（如「机动」「魂食」「干涉」「解放」的具体规则、昼/夜行动约束），先查本地规则库再回答：
```
python "<skill_dir>\scripts\rule_ref.py" --q "<行动类别或规则关键词>"
```
库为 `knowledge/`（含 规则书.md 第一章 回合规则·第三节 行动类别）与根目录 `判例.md`；引用时标注「文件 > 标题」出处，查不到就明说，由 GM 裁决。

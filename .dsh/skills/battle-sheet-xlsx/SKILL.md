# 战斗表辅助与 AI 判定（battle-sheet-xlsx）

战斗表 Excel 的「双方战斗表」属性格是公式，从「戰鬥計算」名单表（M列=角色名，N~T=等级/筋力/耐力/敏捷/魔力/幸运/宝具）自动取值。所以**自动填属性 = 更新名单 + 填参战位**，总值/辅助减半由 Excel 自动算。

## 默认文件

- 战斗表：`X:\dev\dev\fate-gm-helper-main\1.15\战斗表.xlsx`（三国杯用这份，名单里已有本杯角色）
- 判定记录：`X:\dev\dev\fate-gm-helper-main\1.15\三国杯战斗判定记录.md`
- 战斗交接：`X:\dev\dev\fate-gm-helper-main\1.15\三国杯战斗交接.md`
- 问题总结：`X:\dev\dev\fate-gm-helper-main\1.15\三国杯战斗问题总结.md`（反哺 web 项目用）

## 标准流程

1. **看当前状态**（编队、属性、魔力、胜率链、名单核对）：
   ```
   python "<skill_dir>\scripts\battle_sheet.py" status --file "<战斗表>"
   ```

2. **自动填属性**（用户懒得手填时）：从角色卡读「合计」属性，写入名单；可选同时填参战位：
   ```
   python "<skill_dir>\scripts\battle_sheet.py" fill-stats --file "<战斗表>" --card "<角色卡.xlsx>" --name "<名单角色名>" --side 蓝 --pos 主力
   ```
   用 `--dry-run` 先预览；只更新名单不填参战位用 `--no-slot`。若参战位角色不在名单（status 会标 ✗），用本命令补。

3. **看角色卡技能/宝具**（发动时机是判定顺序的关键）：
   ```
   python "<skill_dir>\scripts\battle_sheet.py" skills --card "<角色卡.xlsx>"
   ```

4. **AI 辅助判定**：用户发来「玩家发动的技能/宝具 + GM 的判定方法」（或让用户把改好的战斗表数据发来）后，按下面检查清单逐项核对，输出：**问题清单** + **建议判定**。全部基于战斗表数据，拿不准的向用户确认，不要臆造规则。

5. **规则查证（防幻觉，必做）**：判定涉及规则细节、技能/宝具效果、时机顺序、魔力/状态规则时，先查本地规则库再下结论，并引用出处：
   ```
   python "<skill_dir>\scripts\rule_ref.py" --q "<技能名或规则关键词>"
   ```
   - 库：`knowledge/`（规则书、从者/御主/礼装/工房/学科库、扩充包、特供资源）+ 根目录 `判例.md`（历史裁决，保持一致）。
   - 返回内容带出处（文件 > 章节标题），引用时标注；需要更完整原文调大 `--max-chars`。
   - 查不到 → 明确标注「规则库未覆盖」，由 GM 裁决，并建议用 `verdict` 记入判定记录、补进 `判例.md`。
   - 若后端已启动，`/api/kb/search?q=`（FTS5 全文检索）可作为补充，但本地 rule_ref 是默认途径。

## 判定检查清单

按此顺序核对，用户最容易错的是**技能/宝具发动时机顺序**：

1. **技能/宝具发动时机顺序**：常驻 → 战斗开始时 → 初始工序 → 主要工序 → 最终工序。同一时机内按「先发先结算」；宝具与技能、双方技能交错时明确谁先谁后。用 `skills` 命令确认每个技能的实际发动时机字段。
2. **属性结算**：主力属性 + 辅助属性减半 = 总值（status 的 属性与总值 区）；对比三项属性得 优/平/劣 → 基础胜率（3优=90、2优1平=80、2优1劣=70、1优2平=60、3平=50、1优1平1劣=50、2平1劣=40、1优2劣=30、1平2劣=20、3劣=10）。
3. **魔力消耗与不足惩罚**：当前魔力-消耗后低于 0 的档位惩罚：高于-20=0、低于-20=-10、低于-40=-20、低于-60=-30、低于-80=-40；单独行动有额外档（-60→-15、-100→-25、-140→-35）。核对 Q~AA 区 属性扣除/单独扣除。
4. **战前修正**：胜补/胜惩（G14/M14、G15/M15）、保底/保穿（R16/R17）。
5. **战术/职阶克制**：双方战斗表 AH~AS 区为职阶参考表，注意「加符/轰击」注记。
6. **最终胜率链**：基础胜率 + 等级差 + 属性差 + 战前/初始/主要胜率补正 → 双方胜率 → 差值减半 → 保底夹取（clamp 到 [己方保底, 100-对方保底]）。核对 D84「辅助胜率正常」、E84「最终工序正常」开关。

## 记录与交接

- 用户确认判定后，追加到判定记录：
  ```
  python "<skill_dir>\scripts\battle_sheet.py" verdict --file "<判定记录>" --append "<判定内容>"
  ```
- 刷新战斗交接文档（含编队/属性/胜率/判定记录）：
  ```
  python "<skill_dir>\scripts\battle_sheet.py" handoff --file "<战斗表>" --out "<交接md>" --verdict "<判定记录>"
  ```

## 问题总结（反哺 web 项目）

每次判定会话结束后，把发现的规律/问题追加到 `1.15/三国杯战斗问题总结.md`，格式：
```
- [日期] 现象：… | 原因/规则点：… | 对 web 项目（backend-node/frontend）的改进建议：…
```
重点记录：容易判错的时机顺序、Excel 公式与直觉不一致的地方、web 项目战斗表已覆盖/未覆盖的点。这个文档是用户改进 fate-gm-helper 的输入。

## 注意事项

- 脚本只改：战斗表 xlsx（名单/参战位）、判定记录 md、交接 md；不碰其他文件。改前可用 `--dry-run` 预览。
- 战斗表默认是用户正在用的文件，fill-stats 写之前先确认名单里角色名与参战位一致。
- 判定建议必须标注依据（哪条检查清单/哪个格子数据/规则库出处），复杂条件交给 GM 裁决，AI 不替 GM 拍板。
- 规则查证优先：宁可在 rule_ref 上多花一步，也不要凭记忆下判断。引用规则时给出「文件 > 标题」出处。
